From extracted footprints to clean longitudinal cell tracks.

This guide covers the complete workflow: building a portable HDF5 database from CaImAn, Minian, or MIN1PIPE outputs, cleaning and merging components, aligning fields of view, matching cells across sessions, and safely saving a curated result.

The important mental model

Raw input, in-memory work, one curated checkpoint

Treat the raw database as the reproducible source. Interactive changes are accumulated in a shared working state and immediately follow you between tabs. The header Save button writes a coordinated _curated checkpoint.

CaImAn / Minian / MIN1PIPE

In-memory workspace
Curated HDF5 + matches

Raw Preview

Use it for comparison. Cleaning, merges, alignment and matching are intended for the working copy, not the raw source.

Working Copy

All tabs read the same in-memory cell and alignment state. Changing tabs does not require an intermediate disk write.

Save checkpoint

Persists cleaning, merges, alignments and cell matching together. Undo/redo history is cleared only after a successful checkpoint.

Safety rule: keep an untouched raw database. If a raw file is selected, the dashboard establishes or uses its sibling _curated file before a mutating save.
Recommended order

Quick start

1
Open a database.

Click Browse and choose the database built by the Database Builder. Select Working Copy for normal work.

2
Select a cohort, then an animal.

The animal list is restricted to the selected cohort. This cohort/animal pair scopes the workspace.

3
Clean each session and inspect Overview.

Remove artifacts and merge duplicated detections before alignment and matching.

4
Align sessions.

Choose a reference, test Direct or Sequential alignment, review MIP and footprint NCC, and make small manual corrections if needed.

5
Match cells across all sessions.

Tune thresholds, inspect coverage and distributions, resolve intrasession conflicts, then rerun matching when necessary.

6
Save once satisfied.

The header checkpoint saves the cross-tab state. Until then, use undo/redo freely.

Tab 1

Cell Cleaning & Merging

This tab removes artifact components and combines multiple detections that represent one biological cell. Changes are reflected in alignment and matching immediately.

Individual session

Select a session in the left list when an operation should affect only that session. Pairwise traces and metrics also have the clearest interpretation here.

Overview (all sessions)

Select Overview to display the sessions in their current aligned coordinates. A selection can include components from many sessions; each edit is routed back to the owning session.

Selecting cells

  • Left-click a footprint to select it; use the on-canvas instructions for multi-selection and ellipse selection.
  • Scroll to zoom and right-drag to pan. Zoom and pan can be synchronized with the MIP.
  • When exactly two cells are selected, inspect centroid distance, temporal correlation and temporal traces before merging.

Overview performance: it loads aggregate display matrices and keeps cell ownership metadata instead of treating the overview as a new session. For the snappiest review, use an individual session for trace-heavy work and Overview for cross-session spatial screening.
Tab 2

Session Alignment

Alignment puts every field of view into a common coordinate system. Use the MIP and summed spatial footprints as complementary evidence: a high score in one view does not always imply a biologically good registration.

Direct versus Sequential

Direct to Reference

Every target session is registered independently to one reference session.

Use when: fields of view are already similar, or when you want simple, independent transforms with no propagated error.

Sequential (neighbour)

The algorithm crawls outward from the selected root. Each session is registered to its adjacent session, because nearby sessions usually share more structure.

Use when: early and late sessions differ too much for reliable direct registration.

Sequential interpretation: the displayed comparison and per-step NCC use the neighbouring session that the target was mapped to. The stored accumulated transform still places the target in the root session’s global coordinate frame.

Recommended procedure

  1. Put sessions in chronological or biologically meaningful order using the arrows in the session list.
  2. Choose a stable, representative Reference Session. In Sequential mode this is the crawl root.
  3. Start with Translation-only and MIP. Add rotation or scaling only when the images demonstrate that they are needed.
  4. Run alignment in Overview to process all sessions, then inspect difficult sessions individually.
  5. Compare MIP NCC and SF NCC, plus the actual before/after images. NCC is a guide, not the final decision.
  6. Use manual arrow, rotation and scale nudges for small corrections. These edits are undoable.

Tab 3

Multi-Session Cell Matching

Matching is deliberately an Overview/all-session workflow. There is no session list in this tab: every ordered session for the selected cohort and animal participates.

Core parameters

ParameterWhat it controlsTuning effect
Max Distance LimitMaximum centroid displacement considered for a candidate association.Lower is stricter; higher admits more distant candidates.
Min Spatial OverlapRequired similarity/overlap between aligned spatial footprints.Higher is stricter and may reduce false matches.
Cost Weight (Dist/Overlap)Balances normalized centroid distance against footprint mismatch.Move toward the feature that is more reliable in your preparation.
Overlap MetricCosine similarity uses continuous footprint intensity; Jaccard uses binary intersection-over-union.Cosine retains shape/intensity detail; Jaccard emphasizes shared support.

Reading the result

  • Total is the number of master tracks. Matched tracks appear in at least two sessions; Unmatched tracks appear in only one.
  • Multi-session coverage is the percentage of master tracks present in at least two sessions. The optimizer log reports this alongside its score and thresholds.
  • The presence heatmap shows sessions by master-cell row. Select a row to inspect its footprints and centroid path.
  • Centroid Distance: Matched Cells vs All Other Cells and Footprint Similarity: Matched Cells vs All Other Cells show how well the solution separates accepted associations from alternatives.

Conflict review and intrasession merges

When two master tracks contain likely duplicates in the same session, use Check it out. The conflict view selects both local cells and loads their temporal traces plus distance/correlation/overlap metrics. Apply a single merge or all reviewed merges, rerun matching, and verify that the track structure improves.

Do not merge across biological sessions. A master track links identities across sessions. The actual footprint/trace merge occurs only between duplicated components inside the same session.

Undoing a bad match

Matching executions and merge commits enter the shared history. Press Ctrl+Z or use the header Undo button before saving. After undo, inspect counts, coverage, heatmap and distributions again.

Deleting selected cell groups

Select one or more master-cell rows in the Tracked Cell List and click Delete Selected Cell Groups. Every constituent cell in those groups is discarded from its owning session, remaining local indices are remapped, and matching counts, coverage, distributions and session badges update immediately. The operation stays in memory and can be undone until Save.

Input preparation

Database Builder

The builder scans session folders for configurable analysis-result patterns, maps folder depths to the four database identity fields, validates arrays, and writes a chunked HDF5 database that the dashboard can open.

Launch

Run db-builder. The interface opens automatically at http://127.0.0.1:8001; use db-builder --port PORT if that port is occupied.

Four-step build

  1. Select Session Folder & Pipeline. Point to a representative session folder and edit the supplied recursive result pattern if your analysis output uses another name or location. The defaults are caiman-analysis/**/caiman_results.hdf5, minian-analysis/**/A.zarr, and **/*_data_processed*.mat. A pattern may identify a file or folder; when several results match within a session, the newest by modification time is selected.
  2. Discover Path Structure. Map folder levels to CohortName, MouseName, SessionType, SessionNumber, Ignore, or Split. Supply global values when a field is not encoded in the path.
  3. Choose Output File. Select a portable .h5 location and optionally configure per-session stimulus tables or one hierarchy-matched stimulus file.
  4. Build. Review the live log. Duplicate destinations and incompatible required arrays are reported per session.

Supported inputs

CaImAn

Maps A, C, optional S/F_dff, and aligned idx_components, SNR_comp, r_values, and cnn_preds. Native quality values remain supplemental CaImAn evidence.

Minian

Maps A.zarr, C.zarr, max_proj.zarr, and optional S.zarr.

MIN1PIPE

Maps roifn, sigfn, and imax, and retains optional spkfn and dff. Classic and v7.3 MAT files are supported. If the default wildcard finds both processed and refined results, the newest file is used.

Optional stimulus input

Per-session CSV/XLSX tables use columns frame and stimulus; frames are positive 1-based integers and multiple stimuli may share a frame. A combined MAT/HDF5 file may mirror Database/Cohort/Mouse/SessionType/SessionNumber/StimulusData, with one frame vector per valid stimulus name. Invalid table rows are skipped with row-specific warnings.

Storage choices

float32 or float64gzip, lzf or no compressionreplace, skip or error on existing session

The builder writes sessions through a temporary group and swaps them into place only after the full session is valid. Existing content can therefore be preserved if a session write fails.

Reusable mapping configurations

Save a mapping configuration when multiple cohorts follow the same folder convention. Configurations are JSON and contain the path-depth rules, global values and build options; keep machine-specific root/output paths out of shared example configs.

On-disk contract

HDF5 data format

Database/
└── <CohortName>/
    └── <MouseName>/
        └── <SessionType>/
            └── <SessionNumber>/
                └── CalciumData/
                    ├── SpatialFootprints   # N × width × height on disk
                    ├── TemporalFootprints  # N × time
                    └── MaxProjection       # width × height on disk

Schema 1.2 also permits cell-aligned DeconvolvedEvents and DeltaFOverF, stores common metrics under CalciumData/CellQuality, stores aligned native evidence under optional CellQuality/Source, and stores optional named frame arrays in the session-level StimulusData group.

FootprintArea counts support pixels above 20% of the footprint peak; FootprintEccentricity describes elongation of that support; TemporalContrast divides the 99th-percentile amplitude above the median by the trace standard deviation. Low contrast indicates a trace without strong high excursions and can be flagged for review. Native CaImAn SNR is retained separately and is not assumed comparable across pipelines. Source Accepted uses 1/0/-1 for accepted/rejected/unknown; a newly merged cell receives unknown/NaN source values because CaImAn did not evaluate that derived component.

The builder accepts loader arrays as spatial (N,H,W), temporal (N,T), and MIP (H,W), validates matching cell/FOV dimensions, and transposes spatial images and MIP for the MATLAB-compatible on-disk convention.

Session attributes

Source relative path, analysis type, MIP source, cell count and frame count document provenance.

Database attributes

Schema name/version, builder identity and last-build timestamp support future compatibility checks.

Runtime data flow

Browser action
  → FastAPI route in main.py
  → workspace transaction (in-memory source of current truth)
  → cache invalidation / derived alignment or matching calculation
  → JSON response and canvas/chart rerender
  → header Save
  → SaveCoordinator snapshot
  → curated HDF5 + matching result file

Safe extension pattern

  1. Add or reuse a small request/response contract.
  2. Load only the requested cohort/animal/session arrays.
  3. Perform the mutation inside a workspace transaction and name it for Undo.
  4. Invalidate only derived caches affected by that domain.
  5. Render from the returned/current workspace state.
  6. Add a characterization or regression test before changing numerical behavior.

Keeping the UI responsive

Performance and memory notes

  • Session-local loading: temporal traces and full arrays should be requested for the active session/cells, not for every session in advance.
  • Overview aggregates: use combined display matrices and ownership indices; avoid duplicating complete session data solely for rendering.
  • Shared cache scope: cohort and animal must be part of cache keys to prevent stale cross-cohort results.
  • Debounced NCC: manual alignment nudges schedule NCC asynchronously so canvas movement stays responsive.
  • Targeted invalidation: a cell merge invalidates matching for that animal, while unrelated cached sessions remain reusable.
  • Chunked HDF5: spatial footprints are chunked by cell and images are compressed, supporting partial access and smaller portable files.
  • One save: in-memory editing avoids repeated network-drive HDF5 rewrites between tabs.
Common problems

Troubleshooting

The cohort has no animals

Confirm that the selected database contains Database/<cohort>/<animal>. Switch cohort and reselect the database if needed. The animal menu intentionally filters by cohort.

Sequential NCC or comparison looks wrong

Confirm session order first. Sequential mode compares a target to its crawl neighbour for visualization and step NCC, while accumulated transforms remain anchored to the chosen root.

Temporal traces do not appear in a conflict

Open Check it out from an intrasession conflict and ensure two local cells are selected. The trace endpoint requires the owning cohort, animal, session type, session name and both cell indices.

Save is disabled

No workspace mutation is pending, or no cohort/animal working scope is active. Make a working-copy edit and check the Unsaved indicator.

A build finds no sessions

Verify the selected pipeline, recursive result pattern, and discovered depth rules. Test the pattern against the representative session first. CaImAn expects caiman_results.hdf5; Minian expects the three Zarr datasets.

A build reports duplicate destinations

Two source folders mapped to the same cohort/animal/session-type/session-number key. Correct the depth mapping or split rule; do not suppress the collision.

The app is slow on a network share

Keep intermediate edits in memory, use individual-session trace views, prefer float32/compression where precision policy permits, and avoid repeated disk checkpoints during exploration.
